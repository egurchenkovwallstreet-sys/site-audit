# Глубина сканирования: от чеклиста к «машине проверки»

## Сейчас (узкий фактический слой)

- **152-ФЗ:** 4 бинарных проверки (политика есть/нет, cookie+аналитика, формы без согласия, иностр. SDK).
- **Техника:** заголовки и cookie в основном с **ответа точки входа**.
- **Не делаем:** разбор текста политики, качество согласий, реестр РКН, активные уязвимости (ZAP/Nuclei).

Итог — на многих сайтах **один и тот же набор** (нет CSP, нет политики, Метрика без баннера). Это не «все одинаковые», а **одинаково узкий детектор**.

## Принципы

1. **Нет текста — нет факта** (антибот: `privacy_found` без HTML → не штрафовать за «пустую политику»).
2. **Отдельные находки** на каждый реально различимый риск, не один мега-пункт.
3. **Регрессия** `regression_urls.json` после каждой волны.
4. **Деплой** на VPS после итерации (`deploy-workflow.md`).

## Метрика «не шаблон»

На эталонах (example, okno, Darom, cian, «хороший» корпоративный сайт) **разные** списки findings и разные суммы; на антиботе — честный scope без зелёного «всё чисто».
