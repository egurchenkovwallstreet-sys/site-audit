# ТЗ: подпроект «Машина уведомлений» (Outreach)

**Проект:** Сервис проверки сайтов (site-audit, 152-ФЗ + технические риски).  
**Статус:** отложено — **реализация только после полноценного запуска основного сервиса** (фаза A завершена, приёмка UI, стабильный прод, при необходимости — фаза B: отчёты/оплата по основному ТЗ).

**Связь с основным продуктом:** машина не заменяет пользовательский скан. Она привлекает владельцев сайтов на **лендинг основного сервиса** (название + ссылка в письме). **Отчёт, `scan_id` и LLM в цепочке письма не используются** — экономия токенов и развязка от платного отчёта.

---

## 1. Цель

Автоматизированный конвейер:

1. Берёт из очереди **сайты российских предпринимателей** (см. §4).
2. Проверяет наличие **e-mail** на сайте; без почты полный скан не выполняется.
3. При наличии почты — **rule-based скан** (тот же движок, что у основного сервиса: compliance + security, **без Playwright** в outreach-режиме).
4. При выполнении порогов — **одно письмо** по шаблону (частичный результат: две суммы, без перечисления находок).
5. Получатель переходит на **основной сайт сервиса** и при желании запускает проверку / покупает отчёт сам.

---

## 2. Инфраструктура и риски (согласовано)

| Требование | Решение |
|------------|---------|
| Основной сервис | Отдельный **домен/VPS/IP** — сайт, API, оплата, отчёты пользователя. |
| Исходящая почта | **Отдельный почтовый домен** (запасные домены для замены при блокировке отправителя). SPF/DKIM/DMARC только на почтовом домене. |
| Связь в письме | Только **название сервиса** и **ссылка на основной лендинг** (без ссылки на готовый отчёт). |
| SMTP | **Свой** (без обязательного платного ESP); риски доставляемости принимает заказчик. |
| Частота отправки | **Обязательно:** не реже **1 письма каждые 10 минут**; **не чаще** логики «≥ 10 минут** с момента предыдущей успешной отправки**. Рекомендуемый джиттер 9–10 мин (опционально). |
| Скорость перебора сайтов | **Не ограничивается** ради почты; ограничена только **отправка**. |
| Буфер готовых кандидатов | **Не более 6**; жизнь кандидата — **до отправки**; после send — **немедленное удаление** из буфера. |

После каждой отправки — **сразу** поиск следующего претендента и дозаполнение буфера до 6, с ожиданием до разрешённого момента следующего send.

## 3. Конвейер обработки домена

### 3.1. Порядок шагов

```
1. Достать домен из очереди (с учётом next_* дат и стоп-листов)
2. Лёгкий fetch: главная + контакты (как CONTACT_FALLBACK_PATHS в основном сканере)
3. Признак «российский предприниматель» (§4)
   → НЕТ → rejected_not_ru, НИКОГДА не возвращать
4. Извлечь e-mail в контактах
   → НЕТ → no_email, next_probe_at = +6 месяцев, полный скан НЕ делать
5. Полный скан (compliance + security), outreach: без Playwright
6. Доступ: антибот / pages_checked = 0 / только type=access
   → skipped_no_content, далее по правилу повтора (как для неуспешного скана без send)
7. Посчитать compliance_total, breach_total (§5)
8. Решение о письме (§5.3)
   → не слать → отложенная проверка (§6)
   → слать → положить в буфер (если < 6 и нет блокировки по §6.3)
9. Планировщик send: каждые ≥10 мин брать голову буфера → SMTP → удалить из буфера → next_send_allowed_at = +6 месяцев
```

### 3.2. Переиспользование основного кода

- Скан: `run_compliance_scan` / тот же checker, отдельный флаг `mode=outreach` (без Playwright, без сохранения публичного отчёта для ссылки).
- Суммы: как в UI — `sumCompliancePenalties`, `sumBreachPenalties` (аналог `frontend/src/lib/findingRisk.ts`).
- `type=access` не входит в суммы и не является поводом для письма.

## 4. Определение «сайт российского предпринимателя»

### 4.1. Доверие зоне

- **`.ru`**, **`.рф`** — **100% доверие** (признаки из §4.2 не требуются для допуска в цепочку «почта → скан»).

### 4.2. Остальные зоны (`.com`, `.online`, …)

**Достаточно одного** признака на лёгком проходе (OR):

| № | Признак | Критерий |
|---|---------|----------|
| 1 | ОГРНИП | Подпись + 15 цифр |
| 2 | ОГРН | Подпись + 13 цифр |
| 3 | ИНН | Подпись + 10 или 12 цифр |
| 4 | Телефон РФ | +7 / 8 (XXX), 10 цифр номера |
| 5 | Адрес в РФ | 6-значный индекс + маркеры (Россия, РФ, г., ул., обл., д., оф., пр., пер.) |

**Не прошёл** → `rejected_not_ru`, **никогда** не ставить снова в очередь.

Дополнительные сигналы (₽, 152-ФЗ, ЮKassa и т.д.) — только для логов, **не** для допуска.

### 4.3. E-mail

- **Любой** адрес, найденный в контактах сайта (`mailto:`, текст).
- Валидация формата; фильтр мусора (example.com, noreply без смысла — по белому списку паттернов).

## 5. Пороги и текст письма

### 5.1. Суммы

- **compliance_total** — сумма `max_penalty` по findings `type=compliance`.
- **breach_total** — сумма `max_penalty` по findings `type=security`.

### 5.2. Письмо не отправлять, если

- `compliance_total + breach_total == 0` (обе нули → отложенная повторная проверка, §6).
- Домен в **стоп-листе** (отписка).
- `now < next_send_allowed_at` (уже писали менее 6 мес назад).

### 5.3. Письмо отправлять, если

- **compliance_total > 0**, **или**
- **compliance_total == 0** и **breach_total >= 100_000** ₽.

### 5.4. Содержимое письма (без перечисления находок)

**Тема (фиксированная, маркетинг):**  
`Роскомнадзор все чаще выписывает миллионные штрафы бизнесу`

**Тело:**

- Ввод: контекст проверок, автоматизированный ресурс, призыв проверить сайт (~5 мин).
- **Две цифры** (как на первичном скане), **без** списка cookie/HSTS/форм:
  - Если **compliance_total > 0**: сайт в зоне риска по **152-ФЗ**, штрафы **до {compliance_total} ₽**.
  - Если **compliance_total == 0** и **breach_total >= 100_000**: явно — **на данный момент по фактам штрафов замечаний не зафиксировано**, но есть **технические проблемы / уязвимости**, риск утечки данных, **до {breach_total} ₽** при реализации сценария.
  - Если **оба > 0**: оба абзаца.
- **Одна ссылка** на **основной** лендинг сервиса (UTM: `utm_source=outreach&utm_medium=email` — опционально).
- Дисклеймер: автоматическая проверка, не юридическая консультация; суммы — ориентир по справочнику КоАП.

**Не делать:** ссылка на отчёт, `scan_id`, GigaChat, PDF, перечисление статей КоАП по пунктам.

### 5.5. Ручной тест с экрана скана (фаза A, до машины)

- [x] UI: у каждого адреса в блоке «E-mail на сайте» кнопка **«Отправить письмо»**.
- [x] API: `POST /api/scans/{id}/send-preview-email` `{ "to_email": "..." }` — тот же шаблон §5.4, суммы из findings скана.
- [x] Отправка только на адреса из `contact_emails` этого скана; cooldown 90 с.
- [x] SMTP: `docs/smtp-setup.md`, переменные в `.env` (на проде настраивает заказчик).

## 6. Состояния домена и повторы

| Статус | Повтор |
|--------|--------|
| `rejected_not_ru` | **никогда** |
| `opted_out` (отписка) | **никогда** |
| `no_email` | **через 6 месяцев** (лёгкий probe) |
| Скан ок, **обе суммы 0** | **отложенная** повторная проверка (срок настройки, напр. 30–90 дней — зафиксировать при реализации) |
| **Письмо отправлено** | повторная отправка **не ранее 6 месяцев** (`next_send_allowed_at`) |
| Антибот / нет контента | повтор с разумной отсрочкой (рекомендация: 30 дней, настройка) |

### 6.1. Буфер

- Макс. **6** записей.
- Критерий попадания: §3 + §5.3 + не в стопе + `next_send_allowed_at` в прошлом.
- **Удаление:** сразу после успешного SMTP send.

### 6.2. Отписка

- Ссылка/страница «больше не писать» (на основном или почтовом домене).
- Вносит **домен** (и при необходимости e-mail) в `opted_out`.

## 7. Компоненты (реализация — после запуска основного сервиса)

| Компонент | Описание |
|-----------|----------|
| `outreach_targets` | Очередь доменов, статус, даты next_*, last_sent_at |
| `outreach_buffer` | До 6 готовых send (domain, email, суммы, snapshot шаблона) |
| `outreach_suppression` | opted_out, rejected_not_ru |
| `email_discover` | Лёгкий парсинг почты + признаки РФ |
| `outreach_worker` | Цикл: обработка очереди + fill buffer |
| `outreach_sender` | Таймер 10 мин, send, удаление из буфера |
| `outreach_templates` | Тема + тело без LLM |
| `mail_transport` | Свой SMTP на отдельном домене |
| Админ (минимум) | Пауза машины, стоп-лист, просмотр буфера/очереди, смена почтового домена |

### 7.1. Отдельные процессы (рекомендация)

- **Worker скана** и **sender** могут быть одним сервисом с двумя циклами или двумя PM2-процессами на VPS outreach/том же VPS с отдельным IP для SMTP.

### 7.2. Импорт очереди

- Источник доменов — отдельная задача (CSV, краул списков, ручной импорт). В ТЗ: API или скрипт `import_targets`, без автоматического «всю РФ за день».
