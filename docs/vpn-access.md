# Сайт не открывается с включённым VPN

Сервер **не** режет VPN по IP (нет ufw/fail2ban/geo в nginx). Симптом «без VPN — ок, с VPN — нет» почти всегда на стороне **DNS или политики VPN**, реже — MTU.

## Быстрая диагностика (Windows, VPN включён)

В PowerShell:

```powershell
nslookup audit152fz.online
curl.exe -I https://audit152fz.online/
curl.exe -I http://194.87.220.206:8080/
```

| Результат | Вероятная причина |
|-----------|-------------------|
| `nslookup` — ошибка / нет IP | **DNS в VPN** не отдаёт домен |
| IP верный, `https://домен` — таймаут, **`:8080` по IP — ок** | снова **DNS** или блок **443** в VPN |
| Оба URL не открываются | VPN **блокирует российские IP** или маршрут |
| Долгая загрузка, обрыв на полпути | **MTU** туннеля (см. ниже) |

## Что сделать пользователю

### 1. DNS в настройках VPN

В приложении VPN отключите «блокировку рекламы / malicious / Safe DNS» **или** задайте DNS вручную:

- `77.88.8.8` / `77.88.8.88` (Яндекс)
- `8.8.8.8` / `1.1.1.1`

Переподключите VPN и обновите страницу.

### 2. Исключение сайта из туннеля (split tunnel)

Если VPN нужен только для части трафика — добавьте **audit152fz.online** (или `194.87.220.206`) в **исключения** / «обход VPN», чтобы браузер ходил напрямую.

Нужно в: AdGuard VPN, Nord, Proton, корпоративный AnyConnect и т.д. (название разное).

### 3. Другой режим VPN

Некоторые клиенты в режиме «зарубежный сервер» **режут доступ к РФ-хостингам**. Попробуйте другой узел или отключите «анти-трекинг только для РФ».

### 4. MTU

На сервере включён **MSS clamp** для ответов с 443. Если всё ещё «висит на загрузке»:

- в VPN клиенте уменьшите MTU (например **1280–1400**);
- или временно отключите VPN для этого сайта (п. 2).

### 5. Устойчивый DNS (опционально, для всех)

Перенос DNS-зоны на **Cloudflare** (бесплатно, только DNS — без прокси оранжевого облака):

- стабильнее резолвится через VPN-DNS;
- инструкция: добавить сайт в Cloudflare, сменить NS в Reg.ru, **A** → `194.87.220.206`.

Прокси Cloudflare (оранжевое облако) — отдельное решение; для ЮKassa позже сверить IP return URL.

## Для поддержки

Пусть пользователь пришлёт (VPN **включён**):

1. Вывод `nslookup audit152fz.online`
2. Открывается ли `https://194.87.220.206:8080/`
3. Название VPN-приложения

Этого достаточно, чтобы отнести к DNS / блок IP / MTU.
